# ЯЕда: Telegram-бот

Задачи: #603 — поиск рецептов, #604 — добавление в избранное,
#303 — контракт бэкенда в [OpenAPI](../docs/bot-openapi.yaml).
Бот использует aiogram 3 и обращается только к нашему серверу.
За основу взят минимальный бот из https://github.com/Voltor2005/for-ifood-bot.

## Что работает

- `/start`: приветствие и меню.
- «🔍 Найти рецепт» или `/search`: поиск по названию или ингредиентам.
- Карточки: название, ингредиенты, шаги, кнопка «⭐ В избранное».
- «⭐ Избранное» или `/favorites`: сохранённые рецепты и кнопки удаления.
- Повторное сохранение не создаёт дубликаты; избранное разделено по Telegram ID.
- Отмена, пустой поиск, нет результатов, неверный ввод, недоступный сервер.
- `/generate`: генерация рецепта через бэкенд с настроенным OpenRouter.
- Информация. История в разработке.

## Запуск для показа (Python 3.12 или новее)

Все команды выполнять из корня IFood. Корневой сервер FastAPI запускать для демо
не нужно. Его зависимости и Python 3.14 не требуются для отдельного бота.

```bash
python -m venv .venv-bot
```

Активировать окружение:

- Windows PowerShell: `.venv-bot\Scripts\Activate.ps1`
- macOS/Linux: `source .venv-bot/bin/activate`

```bash
python -m pip install -r telegram_bot/requirements.txt
```

Скопировать `telegram_bot/.env.example` в `telegram_bot/.env`.
Вставить токен своего бота от @BotFather в строку `BOT_TOKEN=`.
Токен не отправлять в чат и не загружать в GitHub.

Запустить бот вместе с тестовым сервером одной командой:

```bash
python -m telegram_bot --demo
```

Открыть своего бота в Telegram и отправить `/start`.
Не запускать одновременно старого бота с тем же токеном.
Остановка — Ctrl+C.

Для подключения настоящего сервера вместо демонстрации:

```bash
python -m telegram_bot
```

Если нужно запускать процессы раздельно, доступны команды
`python -m telegram_bot.demo_api` и `python -m telegram_bot.bot`.

## Что показать на созвоне

1. `/start` → «🔍 Найти рецепт» → `яйца, помидор`.
2. Бот показывает омлет → нажать «⭐ В избранное».
3. Открыть «⭐ Избранное»: омлет сохранён.
4. Повторить сохранение: в списке по-прежнему один омлет.
5. Удалить рецепт из избранного, открыть список: он пуст.
6. Поиск `несуществующий рецепт`: бот предлагает изменить запрос.
7. «Отмена»: возврат в меню.

В демо всего пять рецептов: омлет, паста, овощной салат, рис с курицей,
банановая овсянка. Избранное сохраняется в `telegram_bot/demo.sqlite3`
между перезапусками. Демо работает только на этом компьютере и не заменяет
бэкенд команды или задачу заполнения БД ста рецептами.

## Подключение сервера команды

В `telegram_bot/.env` укажи `API_BASE_URL` и `BOT_API_KEY` сервера команды.
Бот отправляет ключ в заголовке `X-API-Key`. Запуск с сервером команды:
`python -m telegram_bot`.

Демо и клиент используют `GET /recipes/search`, `POST /recipes/generate`
и `GET/PUT/DELETE /fav` (для изменения избранного ID рецепта входит в путь).
Таймаут запроса — 15 секунд для поиска и избранного, 60 секунд для генерации. Состояние незаконченного диалога хранится
в памяти, избранное — на сервере.

## Сборка контейнера бота

Из корня репозитория:

```bash
docker build -t yaeda-bot telegram_bot
```

При развёртывании передай контейнеру `BOT_TOKEN`, `BOT_API_KEY` и
`API_BASE_URL` через окружение. Подключи бот к той же Docker-сети, что и
бэкенд. Например, если сервис бэкенда называется `backend` и слушает
порт 8080, внутренний адрес будет `http://backend:8080`.
Бот получает сообщения через Telegram polling, поэтому ему не нужен
опубликованный входящий порт.

Для прокси Webshare задай `TELEGRAM_PROXY_URL` в окружении контейнера или в
`telegram_bot/.env` при локальном запуске. Через прокси идут запросы к Telegram.
Запросы к бэкенду идут напрямую на `API_BASE_URL`.

## Проверка без токена Telegram

```bash
python -m unittest discover -s telegram_bot/tests -v
```

Тесты поднимают локальный HTTP-сервер с временной БД и проверяют клиент бота,
поиск, изоляцию пользователей, повторное сохранение/удаление и ошибки.
Дополнительно проверяются обработчики сообщений и настоящая маршрутизация
событий aiogram без обращения к Telegram.
